# 从买家问题选择写作结构

框架只在有助于组织信息时使用。先确定本图或本段回答什么问题，再选择结构；不要求每张图都套 PAS/BAB，或每个产品都出现同一套模块。

## 场景与结构选择

| 场景 | 首要任务 | 可选结构 |
|---|---|---|
| 商品标题（listing 文字字段） | 清楚识别品牌、产品、相关品类、规格 | 品牌/产品名 + 品类/成分 + 关键规格；据实际字段约束压缩 |
| 五点描述 | 覆盖最重要的购买理由与使用信息 | 事实 → 为什么对该买家有用；有证据时才展开功效与机制 |
| 副图 | 回答一个具体问题 | 场景 → 相关事实；问题 → 直接回答；利益 → 对应证据 |
| A+ 图片及正文 | 深入解释副图未展开的信息 | 问题 → 事实 → 解释；用法步骤；可核查维度的比较 |
| Brand Story（独立内容） | 表达真实品牌动机与做法 | 买家目标 → 品牌实际行动 → 与产品的联系；没有资料不编创始故事 |

平台规则与字段限制以 [版式参考](amazon-layout.md) 为准；图片的英语节奏与分层以 [美式编辑指南](american-image-copy.md) 为准。

## 框架何时有用

- **FAB**：Feature → Advantage → Benefit。先确认事实，再判断是否有证据支撑后两步；不能从“含某成分”自动跳到“更好吸收”“效果更强”。只有事实时，事实加使用说明就够了。
- **PAS**：Problem → Agitate → Solution。可用于回答真实使用麻烦；没有必要时跳过 Agitate。不要放大疾病或外貌焦虑，也不要虚构用户正在受苦。
- **BAB**：Before → After → Bridge。可解释准备流程的变化，例如一罐与份装的携带方式；不是功效前后照的默认许可。画面与时间线表达的结果同样需要核对。
- **StoryBrand**：让买家的目标决定故事的重点，品牌只讲真实行动。并非每次 A+ 都要长篇起源故事。
- **4Ps**：Promise → Picture → Proof → Push。用于检查论点是否有证据，而不是强制在图上写购买指令。平台原生购物按钮与手写营销 CTA 分开处理。

## 副图任务库：按本品选择、合并和排序

| 买家问题 | 所需材料 | 可能的图卡 |
|---|---|---|
| 这是什么，为什么与我有关？ | 品类、目标场景、可支持的定位 | 产品与使用场景，或一个主要事实 |
| 一天多少，能用多久？ | 标签份量、包装总数量、用法 | 用量与份数；避免把每份剂量写成每粒 |
| 怎么准备或携带？ | 剂型、包装、标签步骤 | 粉剂准备图、独立份装、携带场景 |
| 是什么味道？ | 本品风味规格；体验词另需材料 | 风味图，或与冲调图合并 |
| 配方里有什么？ | Supplement Facts、成分表 | 关键成分与剂量、清晰标签图；不臆造缺失部分 |
| 我为什么相信这点？ | 对应的报告/研究/有效认证 | 证据图，清楚说明对象与范围 |
| 与其他选择有何不同？ | 同口径、可核查比较资料 | 客观维度比较；无依据则省略，平台场景限制见版式参考 |

图数服从用户任务和可用材料。将最有帮助的购买理由与主要顾虑排在前面；没有独立沟通任务的“生活方式收尾”可以省略。品牌案例中的图序只说明它当时的做法。

## 商品标题与五点

商品标题写产品身份与相关规格，优先保留读者识别产品所需信息；没有“第一个词必须是 P0”的要求。品牌名、产品名、成分名与剂量之间自然组织，不机械拼接搜索词。

五点按用户关心的问题分工，例如：产品身份/主要理由、成分与每份量、包装或使用特点、已有证据、标签用法。事实少时不要为填“研究”“认证”一栏发明内容；不存在证据时可改写为其他已知事实，不必专门宣传“无认证”。

每点小标题可用简短短语或句式大小写，是否全大写服从品牌语气，不作统一要求。简洁为默认，必要的用法条件和限定说明不因编辑预算而删掉。

## 关键词的职责

P0/P1/P2 沿用上游分级，用于检查商品标题、五点和相关正文是否自然覆盖；不要改变关键词本来的产品含义。副图和 A+ 图片标题优先清楚、相关、有吸引力，不为了出现关键词而写成搜索短语。

记录实际使用位置即可，不规定每屏重复次数或每条首词。无词库照常工作；不相关、竞品品牌、剂型错配词统一排除，不能转移到后台词建议中。
