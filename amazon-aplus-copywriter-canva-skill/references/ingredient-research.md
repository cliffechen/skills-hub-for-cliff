# 成分调研方法论：遇到任何新成分，按这个流程查

营销话术（成分链路式损失厌恶）和成分科普都需要讲清"这个成分在身体里怎么起作用"。listing 往往只写结论，这部分要单独调研。本文件只写**方法**，不写任何具体成分的结论；具体结论存到成分档案。

## 0. 先找档案

1. 从 listing 标题、五点和 Supplement Facts 识别**主成分**和**有功效作用的辅助成分**（载体、胶囊壳、着色剂不算）。
2. 查 `references/ingredients/` 有没有对应档案（文件名用英文小写短横线，如 `urolithin-a.md`、`calcium.md`、`magnesium.md`）。
   - **有档案，且核实日期在 12 个月内**：直接用，plan 里注明"沿用档案，核实于 YYYY-MM-DD"。
   - **有档案但过期**：按第 1–3 步快速复核，更新日期。
   - **没有档案**：按第 1–3 步调研。
3. 同一成分的不同形态（如镁的甘氨酸镁 / 柠檬酸镁 / 氧化镁）放在同一份档案里分节写。

## 1. 调研清单（每个成分都查这 8 项）

| # | 要查的问题 | 去哪查（优先级从高到低） | 用在哪里 |
|---|---|---|---|
| 1 | **剂量口径**：有效量和原料量是否不同（元素量 vs 化合物重量）？有没有 %DV？不同形态的元素含量差多少？ | NIH ODS 成分 fact sheet；标签图 | 主文案数字、科普第 6 题 |
| 2 | **来源与转化**：食物/原料来源；身体里要不要转化；转化是否因人而异 | NIH ODS；综述文献 | 科普第 2 题；链路"缺口" |
| 3 | **缺口**：为什么光靠饮食不一定够（摄入普遍不足的公开数据、吸收或转化差异、生活方式消耗） | NIH ODS；USDA/NHANES；综述 | 链路"缺口"；科普第 3 题 |
| 4 | **作用机理**：成分在身体里做什么，用外行能懂的话怎么说，有什么日常类比 | 综述；人体研究 | 链路"作用"；科普第 4 题 |
| 5 | **和年龄的关系**：相关身体功能是否随年龄变化 | 综述；NIH | 链路"年龄"；科普第 5 题 |
| 6 | **允许的功效方向**：listing 已写哪些方向？该成分常见的结构/功能声明有哪些？哪些相邻方向 listing 没写（要拦截）？FDA 是否有该成分的授权健康声明（涉及疾病词，默认不用）？ | listing；FDA 21 CFR 101.72–101.83 授权健康声明；FDA 结构/功能声明指南 | `meta.claims.allowed / blocked`；合规 |
| 7 | **原料与品质风险**：该原料常见的污染物或品质问题（如海藻 → 重金属，鱼油 → 氧化，植物提取 → 标准化含量） | 综述；USP/NSF 检测标准 | 冲突表；检测图写法 |
| 8 | **顾客常见疑虑**：最常见的顾虑（如胃肠不适、和别的补剂一起吃、服用时间）及安全上限（UL） | NIH ODS；对标库 FAQ | 科普展开；设计修改清单 |

调研规则：

- 用 WebSearch 查证，**只保留定性结论**；百分比、人群比例不上图。
- 每条结论记录出处方向（机构或作者、年份、期刊、研究对象），写进事实底座的 `note`。
- 研究对象是动物或体外的，明确写"（动物/体外研究）"，只能用作背景，不写成对人的作用。
- 区分三类来源：listing/标签（本品事实）、通用科普（非 listing）、研究（非本品）。

## 2. 写进 plan（等用户确认）

1. **成分链路**（每个主成分一条）：`缺口 → 作用 → 年龄 → 生活结果`，每一环带 F 编号。
2. **功效方向**：
   - `allowed`：listing 已写的方向，加用户在对话中确认的方向；
   - `blocked`：该成分常见、但 listing 没写的相邻方向（例如某成分 listing 写了 bone，没写 joint / heart / immune），以及成分来源容易被误写成功效的词（例如"由肠道转化"≠"gut health"）。
3. **剂量口径**：图上用哪一个数，%DV 是否写。
4. **原料风险**：是否需要在检测图或冲突表里体现。
5. **多成分分工**：主成分和每个辅助成分各自承担什么角色。

## 3. 写进 JSON 与交付后存档

- JSON 的 `meta.claims`：`{"allowed": ["energy metabolism", ...], "blocked": ["gut health", "digestive", ...]}`。scan_copy 用 `blocked` 拦截营销话术和成分科普里的越界说法；没有 `meta.claims` 时会给 WARN 提醒补上。
- 成分机理事实按 F 编号写进事实底座。
- **用户确认 plan 后**，把结论存成或更新成分档案 `references/ingredients/{成分}.md`（格式见 `references/ingredients/_template.md`），同时写明核实日期。只存用户确认过的结论。
- 修改成分档案属于改动技能本身：存档后告诉用户新增或更新了哪份档案；如果项目有安装副本，同步过去。
