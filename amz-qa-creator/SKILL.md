# 亚马逊 Listing QA 批量生成系统（AMZ-QA-Creator）

核心认知：**QA 不是客服工具，而是流量工具**。只上 10~20 组没有用——100 组起步、默认 200 组、头部卖家几百上千组。

三大价值（生成时的目标函数）：
1. **补充 Listing 埋词空间**——标题/五点放不下的词由 QA 承接；
2. **合法蹭品牌流量**——QA 是"买家问买家答"语境，品牌词可合规出现（Listing 正面绝对不能出现）；
3. **迎合 Alexa/COSMO 语义抓取**——QA 承载海量场景/疑问，留下语义痕迹，覆盖意想不到的搜索意图。

完整方法论见 `references/AMZ-QA-Creator-方法论.md`（开工前建议通读，含词库 sheet 映射表 C-7 与 SerpApi 规则 C-8）。

## 配套脚本（skill 目录 scripts/，Python3 + openpyxl）

| 脚本 | 用途 | 用法 |
|---|---|---|
| `inspect_kws.py` | 解析词库六 sheet xlsx → kws_dump.json | `python inspect_kws.py <词库xlsx路径> <输出json路径>` |
| `serpapi_paa.py` | SerpApi 旁路采 PAA 问句 | `SERPAPI_KEY=<key> python serpapi_paa.py <输出json路径> [种子词txt]` |
| `build_qa_xlsx.py` | 合并批次 + 全量质检 + 导出 xlsx/csv/txt | `python build_qa_xlsx.py <批次目录> <facts.json> <输出前缀>` |

依赖：`pip install openpyxl`（脚本无其他第三方依赖）。所有路径参数化，无硬编码。

## 可调参数（默认值，可按需调整）

- 目标组数：**默认 200，最低 100**；每批次落盘 50 条
- 站点/语言：默认美国站英语（QA 正文全部用英文撰写）
- 单条长度：问 10~25 词；答 40~90 词
- 默认配比（允许跨标签）：参数/功能类 ~25% ｜ 人群/场景类 ~25% ｜ 痛点/信任打消类 ~25% ｜ 长尾疑问/语义痕迹类 ~15% ｜ 品牌词对比类 ~10%
- SerpApi 旁路：默认单次运行 ≤30 次调用；站外语料贡献 QA 占比 ≤20%
- 单一品牌词出现频次 ≤ 组数 15%，且不得连续两条出现同一品牌
- 问句句式：任一开场句式（How/What/Is/Does/Can/Has anyone/Which/Why/Should）占比 ≤30%

## 前置澄清（开工前确认，均有默认值）

1. 目标组数（默认 200）与语言（默认英文）
2. 是否启用 SerpApi 旁路（默认：用户提供 key 即启用，否则跳过）
3. 是否有手动卖点补充（默认无，则从 Listing/VOC 提炼）
4. 输出位置（默认工作区 `output/` 目录）

## 第 0 步：输入识别与校验（2 必要 + 2 可选）

**必要 1：词库六 sheet xlsx**（词库 Skill「amazon-new-listing-keyword-library」的输出）
- 必需 sheet：关键词总库（或 P0/P1/P2 分级 sheet）+ 品牌词与否定清单；
- 兜底：通用中间格式 CSV：`keyword, tier(core/longtail), source, note`；
- 缺失 → 提示用户先运行词库 Skill 或补交词库文件。

**必要 2：ASIN 或完整 Listing 信息（二选一）**
- **首选 ASIN**：Sorftime MCP 三件套——`product_detail`（标题/五点/参数，技巧①原料）+ `product_reviews` + `product_customers_say`（VOC 痛点场景）；
- **Fallback**（MCP 失败 / 新品未上架无 ASIN）：用户手动粘贴，最小字段集 = 标题 / 五点 / 产品描述 / 功能参数规格。

**可选 1：手动卖点补充**——产品优势、需着重突出的点，用于答案侧加权。

**可选 2：SerpApi 旁路**——用户显式提供 SerpApi Key 才启用。**Key 只从环境变量读取、绝不写入任何文件**；运行结束后提醒用户 key 未落盘（测试 key 建议吊销）。

## 第 1 步：词库下漏（sheet → QA 角色映射）

| 词库 sheet | QA 角色 |
|---|---|
| P0 核心词 | `core`：QA 中自然复现，与 Listing 呼应，不堆砌 |
| P1 拓展词（类型标签） | 按类型映射 QA 维度：剂量/形态/工艺→参数类；人群→场景类；信任认证→信任打消类；比价意图→对比类 |
| P2 织网词 | `longtail` 主战场：场景/长尾/疑问词，疑问句式优先改写为"问" |
| 品牌词否定清单 | **品牌词库（接力复用）**，受合规细则约束 |
| 形态错配词 | **排除，不进入 QA 埋词**（买家对比提问的自然语境除外，但埋词列绝不收录） |
| SearchTerm 成品 | 不使用 |
| 语义场景短语组 | 场景语料，直接作为"问"句素材 |

## 第 2 步：产品信息、VOC 与事实锚点

**产出三张原料清单**：
1. **参数清单**：全部功能/成分/剂量/规格/工艺/认证（逐条核对，生成阶段要求全覆盖）；
2. **人群×场景矩阵**：人群 × 场景的语义有效组合；
3. **痛点清单**：VOC 高频差评/疑虑/比较点（按提及频次排序）。

**VOC 获取（含 fallback，实测必用）**：
- 本品 ASIN 评论/CustomersSay 有数据 → 直接用；
- 无数据（新品常见）→ 改用**类目头部竞品 2~3 个**的评论合并提炼（`product_search` 按品牌词库头部品牌检索 ASIN，各拉正/负评论）；痛点是品类级的（无效疑虑/价格/见效慢/辅料肠胃反应等），正评提供场景语言。来源标注 `source=voc`。

**事实锚点 facts.json（防幻觉，必做）**：从 `product_detail` 提取可核验事实写入 `facts.json`，例如：
```json
{"brand":"ZAB","dose_mg":1000,"unit_count":90,"servings":45,"price":49.99,"form":"softgel","flavor":"unflavored","age_range":"adult","asin":"B0H1CSQ1M8"}
```
生成答案中的所有数字/规格必须与此一致；第 5 步质检脚本自动比对，不一致标红打回。**卖家无法确认的事实（认证/产地/退换政策）一律标"建议人工微调"，严禁虚构。**

## 第 3 步：SerpApi 旁路（可选，未给 key 则跳过）

- 种子：P0 + P1 头部词 10~20 个；`engine=google`、`gl=us`、`hl=en`；调用 ≤ 配额（默认 30）；
- 提取 `related_questions`（PAA，核心价值）+ `related_searches`；
- 过滤：含种子词根或语义相关；剔除纯导航、纯品牌查询；
- 标注 `source=google_paa` 进场景语料池。

## 第 4 步：QA 生成（分批落盘 + 断点续跑）

**批次与断点（防止长时间运行中断返工）**：
- 每批 50 条写入 `qa_batch<N>.json`（格式见下），**写完立即更新 `manifest.json`**：`{"batches":[{"file":"qa_batch1.json","count":50,"status":"done"}],"target":200}`；
- 中断/续跑时先读 manifest：**已完成批次跳过，只补缺失批次**；严禁凭记忆续写。

批次条目格式：
```json
{"q":"...","a":"...","t":["参数"],"k":["urolithin a 1000mg"],"d":"剂量","s":"keyword_stock","act":"直接可用"}
```
（t=类型可多标[参数/场景/痛点/长尾/人群/品牌词]；k=埋入关键词；d=覆盖维度；s=来源[keyword_stock/voc/google_paa]；act=直接可用/建议人工微调）

**四合一质检标准（每条必须同时做到）**：
1. 埋入场景/长尾关键词（自然融入）；2. 打消一个具体疑虑；3. 场景化语言（不用参数腔）；4. 留下语义痕迹（人群/场景/意图词）。

**写法要求**：
- 问句 = 真实买家口吻（口语、带具体情境）；答句 = 第一人称体验 + 具体细节（时间/地点/数字/感受），再自然带出参数事实；
- 英文撰写，地道美式口语；度量衡用美制；
- 参数全覆盖：生成后对照参数清单逐条打勾，遗漏补写。

**问句多样性与去 AI 腔（批量质量的生死线）**：
- 问句开场句式分布：任一开场（How/What/Is/Does/Can/Has anyone/Which/Why/Should）占比 ≤30%；
- 答案开头：禁止连续 3 条以上同一模式（如 "I take"/"I've been"）；
- 同一标志性短语（如 "around week 3"、"game changer"）全库复用 ≤5 次；
- 允许轻微口语瑕疵，禁止模板腔排比；每条的第一人称叙事视角（年龄/身份/场景）尽量错开。

**医疗声明双层过滤（合规红线）**：禁用词清单见 `references/banned_words.txt`，分两级——
- **红线词（cure/treat/diagnose/prevent/miracle/guaranteed/FDA approved/cancer 疗效宣称等）**：问与答均不得出现，命中即打回重写；
- **医疗敏感词（具体药名/病名）**：仅允许出现在"用药前请咨询医生"类安全问答中，命中由质检脚本列出、人工复核确认；
- 功效表达一律用结构功能语言（supports / helps maintain），不做疾病治疗宣称。

**品牌词合规细则（红线）**：
1. 只出现在 QA 问答中，绝不写入 Listing 正面文案；
2. 中性句式（"How does this compare to X?"），禁止贬低性对比、禁止绝对化宣称；
3. 单品牌频次 ≤ 组数 15%，不连续出现；品牌词尽量置于问句；
4. 答句基调："不确定对方产品细节，但我们的产品是…（讲自己的事实）"。

## 第 5 步：输出与全量质检（build_qa_xlsx.py 自动执行）

**输出三件套**（默认 `output/QA_<产品>_<日期>`）：
1. **xlsx**：`QA总表`（序号/Question/Answer/QA类型/埋入关键词/覆盖维度/来源标签/建议动作，微调行标黄）+ `统计与质检` sheet；
2. **csv**：同 QA总表，便于程序化处理；
3. **txt**：`序号 + Q + A` 纯文本，便于直接复制进卖家后台。

**质检清单（脚本自动执行，报告写入 xlsx 质检 sheet）**：
- 总数达标；来源占比（google_paa ≤20%）；品牌词频次与不连续；
- 形态错配词混入埋词列检查；问句完全重复 + 前三词 n-gram 重复率检查；
- **敏感词扫描**（红线词 FAIL 列行号 / 医疗敏感词 WARNING 列行号）；
- **事实锚点比对**（答案中 mg/粒数/天数/价格等数字 vs facts.json，不一致标红列行号）；
- 核心参数覆盖核对；建议动作分布统计。

任何 FAIL 项必须修正后重新构建，直至全部 PASS（WARNING 项需人工逐条确认）。

## 关键判断原则

- QA 的主体永远由站内词库 + VOC 供给，站外语料只是增味剂（≤20%）；
- 一条好 QA = 关键词载体 + 信任建设 + 语义痕迹，三者缺一就打回重写；
- 宁可少埋一个词，不可牺牲可读性——QA 首先是"人话"，其次才是容器；
- 品牌词打法是经验性操作，自然语境 + 合理频率是风控底线；
- 涉及健康/用药的内容，"请咨询医生"是唯一正确的答案基调；
- 卖家无法确认的事实宁可标黄，绝不虚构。
