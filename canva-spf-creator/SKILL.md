# Canva SPF Creator

把一份 SPF 资料变成 Canva 里的一页 Supplement Facts 面板。默认：美国站、成人及 4 岁以上儿童的 Daily Value、1600×1600 页面。

## 铁律

1. **先查缺陷，再建页。** 任何来源的 SPF 都要先过第 2 步的缺陷检查。缺陷清单是本 skill 的固定交付物，即使用户只说"照这个做一页"。
2. **不悄悄改事实。** 含量、成分、份量照来源转录。只有两类东西可以直接改并在清单里标 🟢：FDA 规定的顺序和版式、美式拼写和标点。
3. **数算不通或 FDA 必填项缺失，必须指出，页面上用占位符 `XX` 占着。** 不照抄算不通的数，也不把自己重算的数填上去——%DV 与含量对不上时，%DV 位置填 `XX%`，重算结果和反推结果都写在缺陷清单里（"按 10 mg 应为 67%；若 7% 是对的，含量应为 1 mg"），等用户定。缺份数、缺 %DV、缺热量等营养项同样填 `XX`，不估算。带占位符的页面不算可上传的成品，每轮总结都要列出页面上还剩哪些 `XX`。
4. **动手的页面左上角标 `create by canva mcp`。** 克隆出新页后第一件事就是加这行字并保存，再开始排版。作用：让同时在 Canva 里的人知道这页正在被自动编辑、别动它；也让用户一眼分清哪页是本 skill 做的。这行字在画布内，会随页面一起导出——总结里提醒用户定稿导出前删掉，或说一声由你来删。
5. **初版直接保存，再和用户来回改。** Canva 编辑在事务里，不 commit 用户在设计里什么都看不到。建完自己核对预览图没问题就 commit，不停下来等用户批准；用户在 Canva 里看着实物提意见，再在同一页上改、再保存。新页是克隆出来的独立一页，保存它不会影响其他页面。
6. **只动新建的那一页。** 不改模板页，不改其他页，不删页。

## 输入

| 项 | 说明 | 缺了怎么办 |
|---|---|---|
| SPF 资料 | 截图 / Excel / PDF / 文字。可多份 | 必需，没有就停下要 |
| Canva 设计 | 链接（短链先 resolve）、标题，或"刚才那个设计" | 必需 |
| 放在哪 | "第 N 页后面" / "最后" | 默认放最后 |
| 模板页 | 设计里已有的一页 SPF，或用户的 SPF 母版设计 | 自己在设计里找标题为 Supplement Facts 的页；找不到见 `references/canva-build.md` §6 |

## 流程

脚本路径 `${CLAUDE_SKILL_DIR}/scripts/`。Windows 上用 `python`。工作文件放 scratchpad，不放用户项目里。

### 第1步：转录 SPF → `spf.json`

读全部来源（图片用 Read 看，字小就放大再看；Excel 用 openpyxl 读全部单元格和合并区域；PDF 用 pdf skill）。**照抄**：错字、单位、符号、0.07 这种小数都原样记进 `*_stated` 字段。结构见 `scripts/check_spf.py` 文件头。

要记的：产品名、剂型（softgel / capsule / tablet / gummy / powder / liquid）、单粒重量、Serving Size、Servings Per Container、总粒数、每个成分的名称 / 来源形式 / 含量 / 单位 / %DV、专利混合物及其子成分、Other Ingredients 原文、脚注原文、过敏原声明。

来源里没有的字段写 `null`，不要推断。

### 第2步：缺陷检查

```bash
python ${CLAUDE_SKILL_DIR}/scripts/check_spf.py "<spf.json>"
```

脚本输出候选问题，并给出 FDA 顺序排好的成分和重算的 %DV。然后按 `references/fda-spf-rules.md` 的检查表人工过一遍——脚本只管能算的，下面这些靠人判断：

- 成分名是不是 FDA 认可的写法，来源形式是否缺失或写法不规范
- 植物成分有没有部位、提取物有没有标准化信息
- 这个剂型是否该有热量、碳水、糖、钠等营养项（软糖、粉剂、液体、含油软胶囊最常缺）
- Other Ingredients 里有没有含糊写法（香精没标 natural/artificial、明胶没标来源、缺逗号导致成分粘连）
- 来源里的 Other Ingredients 是否混进了本该在表里的活性成分，或反过来
- 过敏原（鱼明胶、大豆卵磷脂、乳、小麦等）是否需要 Contains 声明

每条问题记：严重度、位置、来源原文、问题、建议写法、依据（规则文件的节号）。

| 严重度 | 含义 | 处理 |
|---|---|---|
| 🔴 | 数算不通，或 FDA 必填项缺失 | 页面上填 `XX` 占位，清单里指出并给出算出来的数，请用户确认 |
| 🟡 | 写法不规范、有歧义，需要用户提供信息才能写对 | 保守转录，请用户确认 |
| 🟢 | 顺序、版式、拼写标点，已按 FDA 直接改好 | 告知即可 |

有 🔴 时仍然继续建页（用户能边看版式边补数据），除非缺的是 Serving Size 或全部含量——那就先问。

### 第3步：在 Canva 建页

按 `references/canva-build.md` 做。要点：

1. 用 `merge-designs` 把模板页克隆到目标位置。克隆是**立即生效**的，会直接出现在用户的设计里。
2. 重新读 `page_metadata`，用页面 ID 找到新页现在的页码——用户可能同时在拖动页面，页码会变。
3. 开事务，在左上角加 `create by canva mcp` 标记（做法见 `canva-build.md` §3），**立即 commit**。
4. 再开事务打开新页，按几何位置认出各个槽位（标题、份量两行、表头、每行的名称/含量/%DV、横线、脚注、Other Ingredients、外框）。
5. 改字、删多余行、重排位置、调外框。线条元素要用 `update_line_properties` 移动。
6. 看返回的预览图，逐项对照 `spf.json`：每个数字、每个单位、顺序、有无文字溢出或被遮挡。

面板内容和顺序以 `references/fda-spf-rules.md` §1 为准，模板页只提供字体和视觉风格——模板本身违反 FDA 顺序的地方（如份量两行顺序反了）按 FDA 改。

### 第4步：直接保存 → 回读核验

1. 预览图自查通过后，`edit-design` 传 `finalize: "commit"`（不带 operations）。不等用户确认。
2. 核验，按 `references/canva-build.md` §8：重新读 `page_metadata` 找到新页页码，再开一个事务读该页的结构化数据，**逐个元素核对文字和 top/left/height**，与提交前最后一次返回的 document 对比，核完 cancel 这个事务。只核文字不够——实测出现过文字保存了、个别元素的位置却回到模板坐标的情况。**也不要只看缩略图**，保存后缩略图常是旧的。
3. 发现位置或文字与草稿不一致：在新事务里补改、再 commit、再核验，直到一致。
4. 告诉用户新页现在在第几页。

### 第5步：和用户来回修改

用户看过实物提出修改（补数据、换写法、调版式、发截图指出错位）：

- 在同一个新页上改，改完直接保存并核验。不要再克隆一页，除非用户明确要多一个版本。
- 用户发截图说位置不对时，先读该页当前的结构化数据，对照截图找出是哪个元素、现在的坐标是多少、应该是多少，再动手。不要凭截图猜。
- 用户补了数据（份数、热量、来源形式）：更新 `spf.json`，重跑检查脚本，把对应的 🔴/🟡 从清单里销掉，页面上的占位符换成真值。

### 每轮结束时的对话总结

- 新页在第几页，已保存并核验
- 缺陷清单：🔴 在前，每条一行（来源写的 → 现在填的 → 需要用户确认什么）
- 页面上还剩哪些 `XX` 占位符
- 左上角的 `create by canva mcp` 标记还在，导出前要删
- 受限没做到的事（见 `canva-build.md` §7）

不复述整张 SPF。

## 参考文件

- `references/fda-spf-rules.md`：面板必备内容与顺序、成分排序、%DV 计算与取整、单位、来源形式、专利混合物、剂型对应的营养项、Other Ingredients 写法、缺陷检查表
- `references/daily-values.json`：FDA Daily Value 表与别名、成分排序
- `references/canva-build.md`：克隆模板页、槽位识别、可用操作与坑、排版数值、保存与核验、接口限制
- `scripts/check_spf.py`：%DV 重算、排序、份数算术、单位与拼写扫描
