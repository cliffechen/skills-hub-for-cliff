## 触发条件

# 出口产品海外市场进入战略报告（B2B / B2C 通用）

这个 skill 把"麦肯锡 + 市场战略 + 外贸跨境"的分析框架固化成一套可重复执行的报告生产流程：深度研究 → 按固定 MECE 结构写作 → 五维自检 → 产出客户可直接使用的 HTML 报告。JTBD（待办任务理论）本身对企业采购决策者和个人消费者都成立，只是"任务"的内容不同——企业买家买的是流量/利润/合规/省心，终端消费者买的是省心/信任/身份认同/性价比。报告有双重读者——出口企业自己，以及目标市场的核心客户（可能是经销商/代理商/集成商这类 B2B 渠道伙伴，也可能是零售商/电商平台买手甚至终端消费者本身，取决于商业模式）——所以质量要求很高，不能用套话填充。

## 第一步：确认输入参数

必须明确三个变量才能开始：

- **【产品/产品品类】**
- **【目标市场】**（可以是单一国家，也可以是像"北美（美国/加拿大/墨西哥）"这样的区域组合）
- **【商业模式】**：B2B（卖给经销商/代理商/集成商/工程商等企业买家）、B2C（卖给终端消费者，不管是通过零售/电商渠道分销，还是自己做独立站/跨境电商店铺直达消费者）、还是两者皆有（走多条渠道并行）

商业模式这个变量决定了第四章"客户画像"和第六章"渠道策略"该怎么写——B2B 买家关心的是采购决策链和渠道利润分配，C 端消费者关心的是购买动机和购物旅程，两者的分析框架不能混用。

如果用户的请求里这三个变量任一缺失或过于模糊（比如只说"帮我做个市场报告"，或者只给了产品和市场但没说清是走经销商渠道还是直接卖给消费者），先追问清楚再开始，不要凭空假设——报告后续每一节的结论都建立在这些变量之上，猜错了返工成本极高。

如果目标市场是多国/多子市场组合，报告后续每一章都要对每个子市场分别做细颗粒度分析，不能笼统合并成"北美整体如何如何"——不同国家在关税、认证、消费力上的差异本身就是重要信息，合并处理会让报告显得空泛。

如果用户提供了更多背景（已知的客户类型、当前已出货的国家、竞品名单、预算体量等），全部作为研究输入，不要浪费。

## 第二步：深度研究（不要偷工减料）

这份报告的可信度完全取决于数据质量：

- 用今天的真实日期做"最新"框定；任何随时间变化的信息（关税税率、认证要求、市场规模、竞争格局、渠道占比）都要搜索验证，不要凭训练知识直接作答。
- 研究覆盖面很广（宏观政策、市场规模与竞争、客户画像、产品趋势、渠道生态、风险），如果目标市场是多国组合，还要对每个子国家分别搜索。这类报告天然需要大量搜索（数十次量级属于正常范围），按章节、按子市场系统地规划搜索 query，而不是几个笼统关键词了事。
- 同一个关键数据尽量用多个信息源交叉验证（例如 Statista vs 当地海关/统计局 vs 行业协会白皮书 vs 头部企业财报）。不同来源数字打架时，在报告里明确指出差异原因，并说明你倾向哪个数字、为什么。
- 找不到精确数据时，用逻辑树拆解 + 侧面数据交叉验证给出合理估算区间，并清楚标注"估算区间"——绝不能编造一个看起来精确的数字。

写作前先完整读一遍 `references/quality-and-sourcing.md`，里面是数据引用与自检的完整规则。

## 第三步：按固定结构撰写报告

不要自由发挥报告结构——固定使用 `references/report-structure.md` 中定义的七个章节（执行摘要 / 宏观环境 PESTEL / 市场规模与竞争格局 / B2B 客户画像与 JTBD / 产品功能需求洞察 / 销售渠道与 GTM 策略 / 行动蓝图与风险对冲）。**写作前先完整读一遍这个文件**——它规定了每一节必须回答的具体子问题，跳过任何一个都会让报告显得像模板而非深度分析。

报告正文（不含 HTML 标签）目标篇幅不低于 5000 字/词——这不是凑数要求，而是这类报告应有的信息密度：如果写完发现内容单薄，说明第二步的研究深度不够，回去补搜索，而不是靠套话填充字数。

写作时始终记住报告的双重读者：出口企业自己（内部参考，要能指导决策）+ 目标市场的 B2B 客户（"商业武器"，看完要觉得"这个供应商懂我的市场"）。每一节都要同时满足这两类读者，而不是只谈"我方如何卖货"。

## 第四步：五维自检

写完整份报告后，对照 `references/quality-and-sourcing.md` 里的五个自检维度（数据可信度 / 洞察深度 / 可落地性 / 客户视角 / 逻辑闭环）逐条检查。任何一项不达标，直接修正后再定稿——自检不是摆设，发现问题就要回去改。

## 第五步：产出 HTML 报告

默认输出格式是 HTML（除非用户明确要求 Word / PDF / PPT 等其他格式）。这是给客户看的"商业武器"，不是内部草稿，排版本身要专业、有品牌感，不能是套了 HTML 标签的纯文本堆砌。

- 动手写代码前先完整读一遍 `references/html-design-principles.md`（如果当前环境里也装了独立的 frontend-design skill，内容是一致的，读哪个都可以——内联这份参考文件是为了保证即使环境里没有那个 skill，本 skill 也能独立产出有设计感的报告）。围绕【产品】和【目标市场】本身的行业质感做设计决策（例如 LED 照明 + 北美市场可以从"精密制造 / 能效认证 / 工业信任感"这类线索切入），避免千篇一律的 AI 默认风格（暖米色+衬线大字、纯黑+荧光色、报纸式栏目这三种默认款尤其要避开）。
- 结构建议包含：封面（标题/日期/产品与市场标注）、可跳转的目录导航、每章节清晰的视觉分区、三条"颠覆性洞察"用醒目的引用或卡片样式突出、市场规模与竞争格局的关键数字用简单的 CSS 图表或表格可视化呈现、行动蓝图部分用时间轴或步骤卡片呈现。
- 保证打印/导出 PDF 效果过得去——B2B 场景下客户很可能会打印这份报告去说服自己的老板；B2C/DTC 场景下出口企业自己也可能拿它去对内汇报或对投资人/合作方展示，同样需要经得起打印。
- 因为篇幅长，按"先搭骨架、再逐章节填充"的方式构建 HTML，不要试图一次性生成整个文件。
- 完成后保存到 `/mnt/user-data/outputs/`，文件名体现产品与目标市场（如 `led-lighting-north-america-market-entry-report.html`），并用文件展示工具交付给用户。

## 交付时

交付后可以用 1-2 句话概括这次报告的核心看点（比如三条最颠覆性的洞察是什么），但不要在 HTML 之外重复整份报告内容——报告本体只存在于那份 HTML 文件里。
