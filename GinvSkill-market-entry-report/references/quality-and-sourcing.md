# 数据引用规则

- 每一个关键数字都标注来源类型（如 Statista、欧睿国际、当地海关/统计局数据、行业协会白皮书、上市公司财报等），不允许出现"孤立无来源"的数字。
- 面对多个数据源出现分歧时，不要挑一个直接用——指出差异原因（比如统计口径不同、时间窗口不同），给出你倾向哪个数字以及理由。
- 缺乏精确实时数据时，用逻辑树推演 + 侧面数据交叉验证给出合理估算区间，并明确标注"估算区间"，绝不能编造一个看似精确的数字。

# 五维自检（写完必须过一遍，不是可选项）

1. **数据可信度审查**——每个关键数据是否都标了来源类型？有没有孤立无来源的数字？没有的话补来源或标"估算区间"。
2. **洞察深度审查**——逐条检查"市场洞察"部分：是不是换成任何产品/任何市场都成立的正确废话（比如"要注意市场变化"）？如果是，删掉重写，换成只有结合【产品】和【目标市场】才能得出的具体判断。
3. **可落地性审查**——行动建议是否具体到"明天就能照着干"？还是停留在方向性描述？模糊的地方补充具体执行步骤。
4. **客户视角审查**——报告是否真正站在目标市场核心客户的视角写（B2B 模式下是渠道伙伴，B2C 模式下是终端消费者，两者皆有则两边都要顾到）？客户看完能不能立刻感觉到"这个供应商/品牌懂我的市场"？
5. **逻辑闭环审查**——从宏观环境 → 市场规模 → 客户画像 → 产品需求 → 渠道策略 → 行动蓝图，各章节结论是否前后呼应、没有自相矛盾？

发现任何一项不达标，直接回去修正，再定稿输出。

# 质量优先于速度

这类报告的价值完全取决于深度和具体性。宁可多花搜索次数、多花时间把每一节写扎实，也不要为了尽快结束而用套话填充篇幅——一份"面面俱到但没有信息增量"的报告，对出口企业和目标客户都没有实际价值，还不如不做。
